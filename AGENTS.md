## Feature milestones and commits

These instructions apply to the primary agent and every implementation or review subagent. The primary agent owns the milestone plan, integration and commits; include the current milestone scope and these instructions in delegated tasks.

1. Before implementation, inspect the working tree and current DEV_STATE, then state an ordered milestone plan. For each milestone, name the concrete outcome, scope, dependencies, acceptance checks and intended commit title. Split substantial features into small, cohesive, independently buildable and reviewable increments; a small fix or documentation change may use one milestone. M1–M4 in the design are the original application roadmap, not a requirement to restart completed work.
2. Implement only the current milestone. Include its necessary tests, localization and documentation; avoid unrelated cleanup or leaving a broken intermediate commit. If scope grows, revise the remaining plan before continuing.
3. Run the applicable milestone checklist below. Update README and DEV_STATE with the actual outcome, checks, limitations and next milestone; mark inapplicable checks explicitly rather than claiming they ran.
4. Request a clean-session review subagent (`fork_turns="none"`) after each milestone. Supply AGENTS.md, the design and DEV_STATE paths, the milestone scope, exact diff or baseline, and verification evidence so the reviewer can inspect independently. Resolve material findings and rerun affected checks before committing.
5. Commit each completed, reviewed milestone separately before starting the next. Use a descriptive outcome-based commit title and stage only that milestone's changes, including README and DEV_STATE updates. Do not accumulate all milestones into one final commit or include pre-existing unrelated edits; use selective staging when files overlap. Subagents must not commit shared work independently. Honor an explicit user instruction to leave changes uncommitted, and report any blocked check or commit honestly.
6. Report the milestone commit hash, verification, remaining limitations and next step, then continue through the authorized plan without asking for routine confirmation. Do not push or distribute a preview unless authorized.

## Implementation conventions

- The app display name is literal `dokidoki"`, including the trailing quote. Keep the MangaViewer target, bundle ID, OSLog subsystem and storage paths stable. AppInfo reads native bundle branding/version for UI and reports. `App/AppIcon.icon` is the source for iOS/iPadOS/macOS; its group array is front-to-back. Use opaque artwork and native restrained shadows, no baked glass/refraction. visionOS needs its own three-layer asset; regenerate with `python3 scripts/export-vision-icon.py` after icon edits. See docs/ICON.md.
- About reads the native marketing version and build number from the bundle, displayed as release (build). Use MARKETING_VERSION for the release (currently 0.1.0) and set CURRENT_PROJECT_VERSION to a fresh UTC `date -u +%Y%m%d%H%M%S` timestamp before each distributed preview revision, identically in Debug/Release. Keep that identifier for rebuilds of the same revision; keep bundle identity and storage paths stable across display-name changes.
- Build with Xcode 27.1 / iOS 27.1 SDK in Swift 6 language mode; iOS/macOS/visionOS 26 minimum. Verify iPhone Duo with its actual 27.1 simulator in Device Hub. Use available geometry, native safe areas and system bars, never model/fold-state branches. One native SwiftUI application and one UI-independent MangaCore package.
- Use Apple's native localization: App/Localizable.xcstrings for SwiftUI/explicit String(localized:) UI, InfoPlist.xcstrings for bundle display text, and MangaCore/Localization/*.lproj/Localizable.strings with bundle: .module for package errors. Localize complete messages, including accessibility/ternary/variable text; use catalog plurals instead of English plural concatenation. Keep persisted enum raw values, object keys, identifiers and rule JSON stable. Website titles/metadata/rule names are source data, not localization keys. Update both English and Simplified Chinese resources when adding app text; see docs/LOCALIZATION.md.
- Package resources copy `Resources/Rules` and `Resources/Fixtures` separately. Never copy a directory named `Resources` into the bundle root: Foundation treats it as the resource root and cannot discover the sibling `.lproj` folders. Keep the native `Bundle.module.localizations` regression assertion.
- Cleanup by behavior owner: share actual lifecycle/loading mechanisms, not site/device branches. Core tests use a per-test TestFetcher for ordinary source/resource spies; keep real URLProtocol/WebKit fixtures for transport/session contracts. Parameterize the same contract over object kinds or modes instead of duplicating scenarios. Preserve independent cancellation, policy, migration, image/position regressions; do not add app-only test hooks.
- Prefer native APIs and small cohesive files. No scraper logic in views, arbitrary imported scripts, custom navigation framework, or speculative services.
- Validate at ownership boundaries, not at every internal call. SiteRule is immutable and validates during decoding; use its Hashable value for complete request/session policy identity instead of validating/serializing on image loads. Keep URL/redirect/host checks at resource boundaries and cancellation checks after suspension. App startup, rule-file reads, QR rendering and settings persistence use async core APIs; views never access ObjectStore directly. Keep regressions in their existing owning test flow instead of adding parallel cases for the same behavior.
- My Library is the landing section. Use native `TabView`/`Tab` with `.tabBarOnly` on iOS/iPadOS/visionOS so the system owns floating glass placement and accessibility; macOS keeps its sidebar. Root titles use native inlineLarge toolbar placement; detail screens keep inline titles. Keep separate navigation paths for top-level browsing, but **exactly one app-owned reader session above all sections**. Chapters never belong to tab navigation stacks. Collapse retains source/fraction and cancels offscreen work; resume reuses the same reader. Use native tab bottom accessories on iOS/iPadOS and a bottom ornament on visionOS. Do not build a custom glass tab overlay.
- Top-level order is Library, Browse, Recent, Settings. Library contains saved manga, with starred favorites first; Recent is reading history. Row taps open manga details; a medium circular native Resume/Start button uses the global reader. Library/Recent metadata uses consistent compact line spacing and short relative ages without a Last read prefix. Native List rows render the observed durable MangaObject directly, without clearing/reloading metadata on reappearance. Reserve a fixed transparent cover slot so bitmap arrival/release cannot change row geometry. Library/Recent manga and chapter titles wrap in full; never truncate them to a fixed line count. Library swipe only removes; Recent also offers Star/Unstar. Stars also save titles; unstar keeps them saved. Library removal unsaves; Recent removal only hides history, retaining progress. Reading again unhides history. Persist original-source page counts independently of display plans, and never extract rendered chapters solely to populate list metadata.
- Browse defaults to the first rule in persisted Settings order. Core `SiteObject` supplies normalized browse source references and rule-scoped search from JSON `browse`/`searchURLTemplate`; its load API asks the repository to assemble ordered lists from one or more site pages or legacy directory sources. UI consumes the returned DirectoryObjects; shelves own no loading tasks. SitePageObject caches one fetched page and its directory references, never browser state. A `DirectoryObject` is exactly one list (including search results), with source-defined sorting/pagination; Site owns the collection of directories. Render bounded, lazy cover shelves with full-list links and site switching. Do not infer site home/list/search URLs in Swift. Reordering is a presentation preference, independent of matching priority and recipe revision; it must not invalidate the reader. Hide hosts in rule rows while preserving exact-host enforcement and the import preview.
- Bundled filenames set initial site order; the first rule is the shipped default, adopted once on new/existing installs via a core preference. Preserve later user reordering/removal and do not restore unrelated removed rules automatically.
- Rendered DOM is the default extractor format. Chapter totalCount declares all page identities; unresolved image URLs stay unknown until the page/range is requested. JSON session load/page/scroll strategies choose normal DOM actions, with chapter-only {index} selecting a one-based source page. Preserve resolved sibling pages when caching a range. Recreated directory sessions skip already-cached item keys; compare totals against the merged list. Never wait on animation frames in hidden WebKit views.
- Objects are declarative Codable snapshots, never owners of tasks, browsers or mutable continuation. DirectoryObject.items may be unknown; load(_:using:) delegates range assembly, continuation, cycle checks and deduplication to the shared core context. UI consumes returned snapshots and hasMore; it never tracks next-page URLs or visited keys. Named matcher extractors allow different response formats for one object kind; fetch/admission/parsing must choose the same extractor. API offsets, counter paths and link field mapping are JSON-only. Directory/search lists use native List rows and a plain section footer, never a load-more item cell or custom scroll-offset handler. Near-end row appearance requests one range at a time through DirectoryObject; keep loading/end/retry text in the footer. Retain the loaded ObjectScreen identity and native list position on navigation return; only explicit refresh, key or loadingRevision changes remount content. Reserve transparent cover bounds so decoding cannot resize the row artwork. ScrollOverpull belongs only to reader chapter continuation (20% viewport threshold at finger release).
- Search uses the native directory List/cover-grid presentation in the same typed NavigationStack path as object destinations. Keep submitted search state in AppModel and sorted directory keys in the visible route so tab changes restore them, including macOS view recreation. Directory sorting is optional source data: existing Field selectors provide sortByLinks/sortOrderLinks and selectedSortBy/selectedSortOrder. Hide absent axes; follow directory references through core instead of inventing local sorts or URL parameters. Keep source order, query-bearing identities and old snapshots compatible.
- Directory/search presentation can toggle between native List and adaptive LazyVGrid. Share object previews, sorting, range loading and footer across both layouts; only the grid omits metadata and reserves two truncatable title lines. Persist the layout preference through core. Library/Recent titles still wrap in full.
- Covers preserve their original aspect ratio within UI bounds; no gray framing or forced portrait crop. Round the artwork itself, and use a stable container for asynchronous loading lifecycle. Shelves may reserve transparent space to align titles. CoverImageView takes an ObjectKey, resolves the PageObject and asks it for the cached image; keep this task in the shared cover component instead of adding descriptor-loading state to each surface; avoid the chapter image-processing pipeline for covers.
- Manga rating/status/tags are optional rule-extracted metadata. Preserve source rating scales and status wording; do not infer completion from chapter counts or translate website labels in Swift. Omit missing values, trim blank metadata and deduplicate tags in source order. Use the same typed constructor for full extraction and linked known metadata: site directoryLinks.fields supplies title/mangaLinks; directory mangaLinks.fields supplies title, cover and other manga fields. Keep this bounded two-link graph, not an arbitrary recursive object language. Relative selectors belong to the selected link/item. Keep partial chapters unknown, use core ContentReference.preview for cards, and load details only when needed (legacy links without covers retain fallback). Same-version previews must never downgrade complete directory/manga/cover snapshots or change their original fetch date. Homepage directory excerpts carry isPreview and unknown continuation; opening a list resolves its full sorting/pagination. Keep older snapshots decodable.
- HTML rules use XPath through system libxml2. JSON uses dotted paths. GRDB owns SQLite persistence.
- Object identity is rule-scoped; preserve identifying query parameters. Synthetic page keys must be recoverable through the owner. Reading state survives cache eviction.
- `MangaObject` owns previous/next chapter decisions through its navigation methods. Keep each named chapter list in JSON-supplied reading order and navigate within the selected list. Preserve optional chapterListID in reading positions for overlapping groups; old callers use the first matching list. UI sort order is presentation only. Each group defaults to Smart order: concatenate Unicode decimal digits in each title and sort ascending, with stable numeric ties and unnumbered titles last. Retain source/reverse source options; never mutate source chapter order or adjacency. Display each group with a native sort menu and chapter status; reaching the final loaded display page (or bottom in scroll mode) records completion. Manga details use the same Star action, adaptive cover/metadata and a full-width summary. Opening details jumps to the latest chapter by default, configurable in Settings; explicit Back to manga always reveals the current chapter. Use the public UICollectionView item-index APIs on iOS/iPadOS/visionOS, with UIHostingConfiguration for shared SwiftUI rows. A top arrow, short rule-provided group indexTitle (one/two characters, numbered fallback) and interior dots map directly to item paths. Never split chapter groups into artificial sections for index targets, draw a custom overlay, or inspect private SwiftUI list internals. Use native firstItemInSection headers so group index entries reveal the title; hosted row controls use explicit button styles and collection selection stays disabled. Current chapter highlighting belongs to the native cell background. Use UIKit configurationUpdateHandler observation for personal-state changes and diffable snapshots only for structural changes, never blanket reconfigureItems. Hosted SwiftUI details own their Dynamic Type and scaled metrics. Extend the UIKit chapter scroll surface beneath system bars with SwiftUI container safe-area handling; keep UIKit automatic content insets and native glass controls, without opaque toolbar backplates or manual offset compensation. Dots normally target every 25 rows, capped at eight interior stops per group; UIKit owns index gestures, compression and automatic visibility. macOS keeps one SwiftUI section per group and its native scrollbar. Verify fast scrolling against actual item positions, not chapter numbers (the first source chapter may be numbered 76). The legacy chapterRefs view remains a deduplicated flattened list; readers must not derive adjacent indices or infer order from titles/URLs. MangaObject carries personalState (membership, history, chapter read/ignored states and whole-manga progress). Core persists full personal manga snapshots in mangaLibrary separately from the evictable cache; v6 migrates the legacy tables. GRDB observation publishes personal edits and source catalog updates. Ignored chapters are excluded from percentages; completed-catalog knowledge detects newly added chapters. Reading/Finished/New has its own line and icon below the chapter name. Read/ignored marks are sticky during normal reading; explicit individual/group actions can reset them. Known metadata seeds first personal edits even if the cache declines it; only source upsert replaces an existing complete durable catalog, never an older reader/view snapshot. Cache clearing and rule removal preserve personal state. Old reading positions migrate as in-progress, without invented completions.
- Session resource buffers are passive lookups of already obtained bytes (bounded to four contexts, 24 MiB each). Keep URL, rule policy and referer isolation; covers discovered in a directory retain that logical session URL separately from their manga owner; a miss chooses HTTP or rendered transport through the central sender, never an extra fetch inside an old browser to fill its cache. Cache invalidation discards old resource generations. Metadata and image retention decisions belong only to core's cache layer. Objects carry no TTL/expiry/priority; do not assign lifetime based on the document that supplied known metadata. ObjectStore uses a 64 MiB serialized-payload budget, favoring manga/cover over chapter/page over site/directory, with least-recently-used eviction within priority. Normal loads reuse retained valid snapshots; rule revisions, explicit Refresh/Clear and eviction invalidate them. Cache admission must never decide whether a successfully fetched object can be returned. Batch chapter descriptor reads/touches. Images use a 512 MiB disk budget; keys exclude parsing revision but retain rule ID, allowed hosts, URL and referer, with host validation before every hit. Covers reserve 32 MiB of the 112 MiB decoded budget and outlast content images during disk eviction.
- Keep rendered snapshot parsing/resource decoding and durable reading-state I/O off MainActor with native concurrent core APIs; only WebKit/UI operations require it. Serialize personal edits and progress saves in action order across reader replacement, and await pending writes plus fresh local state before choosing a resumed chapter. GRDB observation supplies library/chapter status to views; do not synchronously reread the full library on page turns or observation updates.
- Core objects/references own loading APIs. Views ask them to load metadata, covers and images; the core cache handles retention/storage and owns the shared image cache. One `RequestSender` admits all app-initiated document/image requests and rendered sessions (default Low: four total/two per initial host; Medium: eight/four; High: sixteen/eight; Unlimited: no app concurrency cap), with one admitted rendered operation and a rolling one-second start budget (eight total, four per initial host) at every level. Core persists/applies the concurrency setting; changing it drains the same queue without canceling active work or invalidating content. Rate-delayed work holds no active slot; only admitted requests spend budget. Use one cancellable ContinuousClock deadline and let other eligible hosts proceed. Use native async results to notify callers, deduplicate identical requests, and cancel transport only after the last consumer leaves. Keep active slots until transport exits; never add independent UI network clients or per-loader budgets. WebKit manages its own internal subresource requests.
- External requests, redirects, and extracted URLs must respect exact allowed hosts. Never export credentials. Do not implement access-control workarounds.
- Hidden rendered-source resource loading defaults on; Settings persists the global override in core. Each object-kind extractor may disable it with rendering.loadAds=false. Only declared hosts may load, ads are never presented or interacted with, and sessions persist by logical URL, full rule/extractor policy and background preference (four contexts, 60-second idle expiry); cancellation, refresh and invalidation close affected browsers. Browser timers/subresources remain WebKit-managed within those bounded retained contexts. Changes cancel old object requests; sender deduplication includes the background policy. Native page image downloads are independent. Keep asynchronous readiness and argument/return observation generic and data-only.
- Verify risky seams with fixture tests, run actual platform builds, and record unavailable simulator/device checks honestly. A disconnected tunnel in `devicectl list devices` may simply be idle; try `device info details` or installation before declaring a paired phone unreachable.
- Use MangaCore ErrorDiagnostics for error-only native logging. Object loading APIs record failed loads; presentation catches must not log them again. Record local action/storage failures at their owning boundary. Exclude cancellations and deliberate cache probes. Never log raw error descriptions/userInfo, page content, credentials, URL paths/queries or local file paths; use fixed operation/reason codes and optional hostnames. Reports use the app's own OSLog subsystem/category for the current process, with no automatic upload; see docs/DIAGNOSTICS.md.
- Anchor UI-test coordinates and frame checks to the native app window, so multi-display devices route events correctly. Keep UI coverage in two distinct journeys: Library/navigation/action wiring, and reader gestures/chrome/position restoration. Test each behavior in its owning journey; use the reader test for the single relaunch check. Keep database compatibility/retention cases in core tests. Preserve actual-image and fractional-position assertions that catch restoration regressions; avoid repeated navigation tours, success screenshots, and test hooks in production code.
- User requested https://www.manhuagui.com/ and https://www.mangacopy.com/ for live testing; deterministic bundled fixtures remain the offline baseline. Verify complete page counts and manga reading order, not just the first lazy image or latest-chapter shortcut.
- Maintain rule-authoring/PROMPT.md and GUIDE.md alongside docs/RULES.md when the parser or authoring workflow changes. Keep this AI/human authoring material outside App/, Packages/, and all target/resources membership. Never commit downloaded third-party pages/artwork or temporary source snapshots.
- Diagnose source failures at the failing layer: compare native error codes and a bounded independent request before editing a parsing recipe. A connection timeout before receiving HTML cannot establish a selector defect or a global site outage.
- **Hard rule: ALL site-specific parsing must live in the object-parsing JSON under `Packages/MangaCore/Sources/MangaCore/Resources/Rules` (or an imported rule).** This includes URL recognition, XPath/selectors, regex captures, named variables, chapter titles/order, filename extensions, CDN/path/query construction, rendering mode, and captured function paths. Never encode a website exception or fallback in Swift, views, transport, or injected bridge code. Add only generic capabilities to the engine; express the website recipe in JSON. Keep the language minimal and data-only, with no imported executable scripts or general expression evaluator.
- Rendered JSON observes normal site behavior and requires a site-created image selected by the rule's readiness XPath. Never manipulate access gates or cookies. Manhuagui's JSON requests desktop content because iPhone requests redirect to a different mobile host/DOM. Preserve exact host restrictions and primary policy errors.
- Image tasks receiving PageObject descriptors must include resource URL/referer in their identity, not just object key. Key-resolved covers reload on key/hint/loadingRevision changes; ObjectScreen remounts refreshed content even when its key is unchanged. Clear stale image state before loading; preserve these invalidation paths when consolidating views. Native task(id:) owns image/object request cancellation; avoid parallel active flags or request tokens for the same lifecycle. Keep periodic Library age updates in their label, not around the list.
- Lazy reader rows must release offscreen bitmap state; an NSCache limit alone does not bound retained SwiftUI state. Keep image/loading/error states inside one stable container and make each scroll target span the viewport, with artwork insets inside it. Prepare the initial target region’s source dimensions before fractional restoration, including manual pairs. Native lazy-stack anchoring handles ordinary image/neighbor changes; only explicit navigation, viewport/preferences changes or replacing the current region should request position restoration. Stage analysis during active scrolling so row geometry and plans change together after interaction. Prefetch distance is a separately persisted core enum: Off, 2 (default), 4 or 8 display pages ahead. Prepare current sources, then forward pages, then one previous page when enabled, bounded to twice (distance + 1) sources. Off keeps visible preparation and explicit overscroll previews, but no speculative pages/chapters. Retain overlapping jobs as pages become visible. PageObject.prepare warms the same core image cache as independent display requests and analyzes off the main executor; never cancel all prefetch on every replan. Cancel obsolete jobs/on collapse and retain shared visible consumers. Never restore scroll position during an active gesture. Keep the native ScrollPosition with the prepared ReaderModel so chapter plans, target and labels publish together. ChapterObject resolves explicit entry intent: resume restores history, next starts at the beginning, previous starts at the end. Toolbar and overscroll share the directional path. Choose source/fraction before preparing plans, artwork and native scroll position; never correct history after publishing the new chapter. Use native ID/edge targets for chapter entry; restore actual fractions from native onGeometryChange target/content coordinates, without timers or independent offset observers. A new gesture supersedes pending restoration. Keep per-pixel fraction bookkeeping unobserved; publish display-index changes for UI/prefetch. Initialize the chapter-scoped native scroll content with the prepared ScrollPosition; do not add layout-readiness observers or post-display corrective jumps.
- Split-page detection/cropping/composition belongs in MangaCore's existing spreadDetect pipeline; DisplayPage.image owns concurrent composition through PageObject image loads. Compare only adjacent sources; join confident left/right artwork edges, removing only measured white seam margins. Preserve original keys/fractions, reading direction, manual overrides and both reading modes. Keep analysis bounded and reject flat/ambiguous borders; see docs/IMAGE_PROCESSING.md for the external basis and thresholds. No site-specific image heuristics in Swift.
- Paged ScrollPosition uses a center anchor so tracking follows the displayed page, rather than a partially visible neighbor. Scope native scroll ownership to the chapter where tracking/interacting began, retaining it across an early idle before deceleration; reset ownership on chapter replacement or explicit restoration/navigation. Idle callbacks may record only for that owning chapter. Reader chrome must not change manga layout geometry. Keep ReaderView and its presentation, chrome, badge and boundary overlays mounted across chapter changes. Key only its scrolling-content Group by ReaderModel.id, so native offset, pan/deceleration and ScrollOverpull state belong to one chapter. Keep its initial geometry observer inside that identity so a resize during preparation reaches the incoming model. A reused ScrollView can overwrite a freshly prepared binding with its old offset before onChange runs. Prepare incoming pages, ScrollPosition and one composed landing image before publishing content; use the same native lifetime for ordinary opens, toolbar and overscroll. Retain that one landing image through native layout until moving away or collapsing; normal rows release bitmaps offscreen. An outgoing deceleration must not become the incoming chapter's user gesture. Keep toolbar content independent of transient pull geometry; native image task appearance owns cancellation, without active-state task-identity restarts. Keep toolbar/status visibility on the persistent presentation; never key or fade the whole reader by chapter identity. Keep the small chapter/page badge visible in immersive mode. Verify differing page aspect ratios in both directions. Reduce Motion skips it. Missing neighbors show a boundary message.
- Preload only adjacent metadata and a boundary image within the selected prefetch distance of each end (next first page, previous last page). Show next-chapter loading/unavailable status in that range; hide the hint when ready. - Keep one primary app window (native `Window` on macOS/visionOS; multiple scenes disabled on iOS).
