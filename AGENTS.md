# MangaViewer development

Read `docs/MangaViewer_DESIGN.md` and `docs/DEV_STATE.md` before changing behavior.
Implement milestones sequentially, with a clean-session review subagent after each milestone. Resolve material findings before committing. Keep DEV_STATE and README accurate in each milestone commit.

- Swift 6, iOS/macOS/visionOS 26 minimum. One native SwiftUI application and one UI-independent MangaCore package.
- Use Apple's native localization: App/Localizable.xcstrings for SwiftUI/explicit String(localized:) UI, InfoPlist.xcstrings for bundle display text, and MangaCore/Localization/*.lproj/Localizable.strings with bundle: .module for package errors. Localize complete messages, including accessibility/ternary/variable text; use catalog plurals instead of English plural concatenation. Keep persisted enum raw values, object keys, identifiers and rule JSON stable. Website titles/metadata/rule names are source data, not localization keys. Update both English and Simplified Chinese resources when adding app text; see docs/LOCALIZATION.md.
- Package resources copy `Resources/Rules` and `Resources/Fixtures` separately. Never copy a directory named `Resources` into the bundle root: Foundation treats it as the resource root and cannot discover the sibling `.lproj` folders. Keep the native `Bundle.module.localizations` regression assertion.
- Prefer native APIs and small cohesive files. No scraper logic in views, arbitrary imported scripts, custom navigation framework, or speculative services.
- My Library is the landing section. Use native `TabView`/`Tab` with `.tabBarOnly` on iOS/iPadOS/visionOS so the system owns floating glass placement and accessibility; macOS keeps its sidebar. Keep separate navigation paths for top-level browsing, but **exactly one app-owned reader session above all sections**. Chapters never belong to tab navigation stacks. Collapse retains source/fraction and cancels offscreen work; resume reuses the same reader. Use native tab bottom accessories on iOS/iPadOS and a bottom ornament on visionOS. Do not build a custom glass tab overlay.
- Top-level order is Library, Browse, Recent, Settings. Library contains saved manga, with starred favorites first; Recent is reading history. Row taps resume through the global reader (or start an unread title's first chapter). Stars also save titles; unstar keeps them saved. Library removal unsaves; Recent removal only hides history, retaining progress. Reading again unhides history. Persist original-source page counts independently of display plans, and never extract rendered chapters solely to populate list metadata.
- Browse defaults to the first rule in persisted Settings order. JSON `browse` supplies named directory URLs; render bounded, lazy cover shelves with full-list links, site switching and explicit rule-scoped search. Do not infer site home/list/search URLs in Swift. Reordering is a presentation preference, independent of matching priority and recipe revision; it must not invalidate the reader. Hide hosts in rule rows while preserving exact-host enforcement and the import preview.
- Search is a native results list in the same typed NavigationStack path as object destinations. Keep submitted search state in AppModel and sorted directory keys in the visible route so tab changes restore them, including macOS view recreation. Directory sorting is optional source data: existing Field selectors provide sortByLinks/sortOrderLinks and selectedSortBy/selectedSortOrder. Hide absent axes; follow directory references through core instead of inventing local sorts or URL parameters. Keep source order, query-bearing identities and old snapshots compatible.
- Manga rating/status/tags are optional rule-extracted metadata. Preserve source rating scales and status wording; do not infer completion from chapter counts or translate website labels in Swift. Omit missing values, trim blank metadata and deduplicate tags in source order. Reuse the manga load for list covers and metadata; keep older snapshots decodable without these fields.
- HTML rules use XPath through system libxml2 (the design's expressed XPath preference supersedes its illustrative CSS/SwiftSoup choice). JSON uses dotted paths. GRDB owns SQLite persistence.
- Object identity is rule-scoped; preserve identifying query parameters. Synthetic page keys must be recoverable through the owner. Reading state survives cache eviction.
- `MangaObject` owns previous/next chapter decisions through its navigation methods. The default follows its rule-supplied `chapterRefs` order; readers must not derive adjacent indices or infer order from titles/URLs.
- Core objects/references own loading APIs. Views ask them to load metadata, covers and images; the repository handles freshness/storage and owns the shared image cache. One `RequestSender` admits all app-initiated document/image requests and rendered sessions (four total, two per initial host, one rendered session). Use native async results to notify callers, deduplicate identical requests, and cancel transport only after the last consumer leaves. Keep active slots until transport exits; never add independent UI network clients or per-loader budgets. WebKit manages its own internal subresource requests.
- External requests, redirects, and extracted URLs must respect exact allowed hosts. Never export credentials. Do not implement access-control workarounds.
- Verify risky seams with fixture tests, run actual platform builds, and record unavailable simulator/device checks honestly.
- Keep UI coverage in two distinct journeys: Library/navigation/action wiring, and reader gestures/chrome/position restoration. Test each behavior in its owning journey; use the reader test for the single relaunch check. Keep database compatibility/retention cases in core tests. Preserve actual-image and fractional-position assertions that catch restoration regressions; avoid repeated navigation tours, success screenshots, and test hooks in production code.
- User requested https://www.manhuagui.com/ for live testing; deterministic bundled fixtures remain the offline baseline.
- **Hard rule: ALL site-specific parsing must live in the object-parsing JSON under `Packages/MangaCore/Sources/MangaCore/Resources/Rules` (or an imported rule).** This includes URL recognition, XPath/selectors, regex captures, named variables, chapter titles/order, filename extensions, CDN/path/query construction, rendering mode, and captured function paths. Never encode a website exception or fallback in Swift, views, transport, or injected bridge code. Add only generic capabilities to the engine; express the website recipe in JSON. Keep the language minimal and data-only, with no imported executable scripts or general expression evaluator.
- Rendered JSON observes normal site behavior and requires a site-created image selected by the rule's readiness XPath. Never manipulate access gates or cookies. Manhuagui's JSON requests desktop content because iPhone requests redirect to a different mobile host/DOM. Preserve exact host restrictions and primary policy errors.
- SwiftUI image task identity must include resource URL, not just object key; clear stale image state before loading. Refresh must invalidate view data even when the chapter key is unchanged.
- Lazy reader rows must release offscreen bitmap state; an NSCache limit alone does not bound retained SwiftUI state. Keep prefetch to a small cancelable neighbor window. Never restore scroll position during an active gesture.
- Reader chrome must not change manga layout geometry. Keep the small chapter/page badge visible in immersive mode. The collapsed accessory uses the manga cover, never the current content page. Metadata canceled on collapse must be retried by the visible accessory or resumed reader. Reader/settings presentation must not force text-input focus on touch platforms; focus is appropriate after an explicit Search or Open URL action.
- Chapter continuation in either mode requires a fresh pull from a settled boundary and 25% viewport overscroll on release; arrival and momentum never reveal/advance. Keep previews outside scrollable content; use native geometry/phases and `.viewAligned(limitBehavior: .alwaysByOne)` for single-page swipes. Fixed-layout title/threshold text stays readable in the exposed gap behind the growing image, without a card or progress bar; clip the early reveal instead of reflowing. Finish enlargement quickly after release; Reduce Motion skips it. Missing neighbors show a boundary message.
- Preload only adjacent metadata and a boundary image near each end (next first page, previous last page). Show next-chapter loading/unavailable status on the last two display pages; hide the hint when ready. Reset canceled pointer pulls with `GestureState`, invalidate superseded animation completions, and prevent outgoing readers from saving or navigating.
- Keep one primary app window (native `Window` on macOS/visionOS; multiple scenes disabled on iOS). The app-owned reader must never be driven by competing window lifecycles. Deduplicated repository requests track consumers; cancel transport when the last consumer leaves, preserving requests still used elsewhere.
- Rule changes must reload open content and cancel old image/prefetch work. Removing a rule purges its cached snapshots transactionally while preserving saved titles and reading state.
- Keep the macOS sandbox's user-selected file read/write entitlement for native import/export. Settings has its own error presentation because it can run in a separate window.

## Required milestone checklist

- [ ] Audit production Swift and injected JavaScript for site names/hosts, DOM IDs, function names, image suffixes, URL patterns, and site-dependent branches. All website parsing recipes must be in JSON; no exceptions. Generic page labels and offline fixture transport are not website parsing rules.
- [ ] Exercise parsing with JSON-driven fixtures, and the requested live source when changing its recipe. Preserve final URL/redirect host checks.
- [ ] Run core tests, affected platform builds, and relevant reader interaction checks. Have a clean-session reviewer check the JSON-only boundary and resolve material findings.
- [ ] For loading changes, verify object-owned APIs, shared sender admission/deduplication, cancellation and exact-host checks. Views must not construct or send network requests.
- [ ] Update README and DEV_STATE with changes, verification, limitations, and next steps before committing.
- [ ] Audit new user-facing text for native localization, full-message placeholders/plurals, and accessibility coverage. Keep source data verbatim and storage identifiers independent of language.
